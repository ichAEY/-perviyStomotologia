# Развёртывание

## Просмотр образца

`npm run build` создаёт `out/` для корня домена. Для GitHub Pages используйте `npm run build:pages`: сборка учитывает подпапку репозитория. Его можно раздать статически на GitHub Pages, Selectel или другом хостинге. Форма в `demo` работает как проверка интерфейса и ничего не отправляет.

Для GitHub Pages включите в Settings → Pages источник GitHub Actions, затем запустите workflow «Publish template preview to GitHub Pages». Workflow публикует демонстрационный шаблон при обновлении main; форма остаётся в demo.

## Сайт клиники с реальными заявками

1. Заполните `public/site-data.js` и установите `mode: 'live'`.
2. Установите Node.js 24 и разместите репозиторий на сервере. Выполните `npm ci`, затем `npm run build`.
3. Задайте переменные из `.env.example` в системе запуска процесса. Файл `.env` автоматически не загружается.
4. Настройте постоянный `DATA_DIR` за пределами публичной папки. Храните базу и резервные копии на согласованной владельцем инфраструктуре.
5. Запускайте `npm start` через systemd или иной менеджер процессов.
6. Поставьте перед процессом HTTPS reverse proxy. Он должен передавать `Origin` посетителя; `PUBLIC_ORIGIN` — точный HTTPS-домен без завершающего слеша.
7. Проверьте `/api/health`, заполнение формы, сохранение заявки и фактическое получение уведомления.

API и статика должны работать на одном origin. Путь формы по умолчанию — `/api/requests`. Не меняйте его на сторонний сборщик без настройки сервера, согласия и маршрута доставки.

## Получатель уведомлений

`REQUEST_WEBHOOK_URL` — HTTPS endpoint, который владелец использует для получения заявок. `REQUEST_WEBHOOK_TOKEN` при необходимости передаётся как Bearer token. Секреты никогда не находятся в `site-data.js` или GitHub.

Пример схемы сообщения (значения вымышлены):

```json
{
  "event": "dentistry.request.created",
  "id": "UUID заявки",
  "phone": "+79990000000",
  "name": "",
  "createdAt": "ISO дата",
  "consentVersion": "Версия согласия"
}
```

Получатель должен распознавать `Idempotency-Key`, возвращать 2xx только после приёма сообщения и обрабатывать повторные доставки без создания дублей. При потере ответа доставка может повториться.

Заявка сохраняется в SQLite до ответа браузеру. Очередь проверяется каждые 15 секунд; интервалы повторных попыток увеличиваются до 6 часов. Перезапуск сервера не стирает очередь. Публичного API чтения заявок нет.

Если уведомления не приходят, проверьте статус очереди и получатель; принятые заявки находятся в базе. Настройте эксплуатационный контроль очереди и резервное копирование. Ограничение частоты учитывает адрес соединения и телефон; за reverse proxy настройте дополнительно ограничение по адресу посетителя на уровне proxy.

## Документы и сроки

Владелец предоставляет документы, сведения о медицинской организации и отдельное согласие на обработку данных. Версия согласия сохраняется с заявкой и датой; архивируйте сам текст каждой версии, меняйте идентификатор при изменении текста.

`REQUEST_RETENTION_DAYS` по умолчанию равен 30 дням; это техническое значение, а не рекомендация закона. Установите согласованный срок. Истёкшие записи удаляются, включая очередь уведомлений. Политику, хранение и получателей данных нужно описать фактически.

Конфигурационная проверка не заменяет проверку достоверности документов клиникой.

## Аналитика

`metrikaId` изначально пуст. После настройки счётчика и документов можно включить базовую Метрику. Успешное серверное принятие вызывает `request_accepted`; телефон, имя и текст согласия не передаются. Webvisor и карта кликов выключены.

## Завершение запуска

Проверьте реальные устройства и размеры 320, 375, 390, 768, 1024, 1440 и 1920 px, горизонтальный экран, клавиатуру, 200% масштаб и режим увеличенного текста. После этого проведите контрольную заявку на собственный тестовый номер, проверьте базу и уведомление администратору.

## Перед выпуском клиники

Перенесённый шаблон пока не содержит отдельного блока врачей и публичного каталога документов. Эти разделы необходимо вывести перед запуском реального медицинского сайта. Значение `live` само по себе не завершает подготовку контента. Метаданные демо закрыты от индексации; перед запуском настройте реальные заголовок, описание, URL и превью.
